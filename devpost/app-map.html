Exception Desk — App Map

Reference route. Snapshot commit: latest on master after build.

What it does

A small Node server serves one ops desk page. You paste or upload exceptions; Triage calls POST /api/triage, which parses the batch, classifies each item (rules in demo mode, optional LLM), links related rows, and returns a priority-sorted queue. The browser keeps approve/edit/reject in localStorage—no money moves.

Flow (one action)

Reference route (3 stops)

  1. public/app.js — search runTriage: builds the POST body from the paste area and renders the queue from the JSON response.
  2. server/triage-run.js — runTriage: parseBatch → per-item triageItem → attachRelatedItems → sort by priority.
  3. server/rules-engine.js — triageWithRules: keywords, amounts (P1 if ≥ $500), disputes/duplicates always P1; sets evidenceLines for the detail panel highlights.

To change this, start here

  • P1 rules or categories → server/rules-engine.js (triageWithRules, P1_AMOUNT).
  • Related-item linking → server/related.js (attachRelatedItems).
  • Queue layout / filters → public/app.js (renderQueue) and public/styles.css.
  • Sample demo data → samples/batch.txt (served by GET /api/sample).

A practice to reuse

Spec criterion: sample batch triages deterministically in demo mode. The HTTP test in test/triage-http.test.js loads samples/batch.txt, POSTs to /api/triage, and asserts item count, P1 volume, and related links—so a plan-first acceptance line became a repeatable command (npm test) instead of a manual demo script.

Run again

npm install && npm start
